Workflows

Four common ways people use calibratedDML

Each card gives the use case, the main Python call, the main R call, and the inferential reason this is the right entry point.

Use-case first, API second.

Workflow 1

Standard estimator from raw data

Use this when your target is a mean potential outcome or treatment-vs-control contrast and you want the package to fit nuisances, cross-fit, calibrate, and run inference for you.

Why this workflow: It is the cleanest default for routine causal analyses when overlap modeling and outcome regression both live inside the package workflow.

Python

CalibratedDML(...).fit(X, A, y)

R

calibrated_dml(data, outcome, treatment, covariates, ...)

Workflow 2

Estimator from supplied nuisance matrices

Use this when you already have cross-fitted nuisance functions, perhaps from a custom econometrics pipeline, and want the package to handle only calibration, debiasing, and inference.

Why this workflow: It cleanly separates nuisance estimation from the inferential step while preserving the calibrated DML machinery.

Python

CalibratedDML(...).fit_from_nuisances(A, y, mu_mat, pi_mat, ...)

R

calibrated_dml_from_nuisances(A, Y, mu_mat, pi_mat, ...)

Workflow 3

Multi-arm treatment with control contrasts

Use the standard estimator when treatment has more than two levels and your estimand is every arm mean plus each treatment-vs-control contrast. The package aligns columns to treatment levels and reports results relative to the chosen control arm.

Why this workflow: It preserves a single nuisance-and-inference pipeline while handling categorical treatment directly.

Python

CalibratedDML(control_level=0, ...)

R

calibrated_dml(..., control_level = 0)

Workflow 4

Adaptive binary-treatment workflow

Use this only for binary treatment when you want plugin or calibrated R-learner style adaptive estimation and are prepared for more delicate inference choices such as jackknife or bootstrap intervals.

Why this workflow: It targets the adaptive or super-efficient regime rather than the routine calibrated DML default.

Python

AdaptiveCalibratedDML(mode="plugin", ...).fit(X, A, y)

R

adaptive_calibrated_dml(data, outcome, treatment, covariates, ...)

Practical Notes

What usually matters in practice

Most workflow decisions reduce to nuisance provenance, treatment structure, and how conservative you want the inference layer to be.

The package is meant for inference with flexible nuisance models, not for ranking-only prediction pipelines.

Cross-fitting matters

If you supply nuisances, the expected path is that they are already cross-fitted. The inferential layer assumes it is working from out-of-fold nuisance estimates.

Propensity modeling is part of the story

The treatment nuisance is not a side detail. The workflow choice should reflect how you are handling overlap and probability modeling.

Inference is an explicit setting

Choose between Wald, bootstrap, and jackknife based on the workflow and how conservative you want the uncertainty layer to be, especially in adaptive binary-treatment analyses.
