Causal Inference And Econometrics

Calibrated debiased machine learning for causal effect inference.

calibratedDML is built for users who want valid causal inference with flexible nuisance estimation. The package targets mean potential outcomes and treatment-vs-control contrasts, calibrates nuisance functions between fitting and debiasing, and supports both R and Python workflows.

Python Main Class

from calibrateddml import CalibratedDML

fit = CalibratedDML(
    control_level=0,
    calibration_method="auto",
    inference="wald",
    random_state=123,
)

fit.fit(X, A, y)
fit.summary()
fit.confint()

Start Here

Choose the estimator family before choosing details

Most users should start with the standard calibrated DML estimator. Adaptive methods are for users who explicitly want a super-efficient tradeoff and are comfortable with more delicate inference behavior.

Standard first, adaptive only when the extra tradeoff is intentional.

Recommended Default

Standard calibrated DML

Use this for routine estimation of arm means and treatment-vs-control contrasts with flexible nuisance models, calibration, and standard inference choices.

  • Python: CalibratedDML
  • R: calibrated_dml()
  • Supports categorical treatment in the standard estimator
  • Works whether nuisances are fit internally or supplied directly

Advanced

Adaptive calibrated DML

Use this only when you specifically want adaptive or super-efficient methods and are prepared for harder interval estimation and less routine uncertainty quantification.

  • Binary-treatment only
  • Python: narrower experimental layer
  • R: broader adaptive and model-backend surface
  • Not the default recommendation for general users

Workflows

Four common ways people use the package

Start from the inferential setup, not from a menu of methods. These are the main entry points for calibratedDML users.

The right workflow depends on your estimand, nuisance pipeline, and whether treatment is binary or multi-arm.

Fit nuisances internally

Use this when you want the package to handle cross-fitting, nuisance estimation, calibration, and debiasing end to end.

Supply nuisance matrices directly

Use this when nuisance functions are estimated elsewhere and you want calibrated DML to focus on the inferential layer.

Multi-arm treatment

Use the standard estimator when treatment has more than two levels and your target is arm means plus control-vs-treatment contrasts.

Adaptive binary treatment

Use the adaptive layer only in binary-treatment settings where you explicitly want plugin or calibrated R-learner variants.

Language Paths

Python and R share the same inferential idea, but not the same surface

Both interfaces implement calibrated debiased machine learning. The main differences are in naming, estimator breadth, and how advanced nuisance-model backends are exposed.

The Python package is cleaner as a package-style API; the R package is broader for advanced modeling workflows.

Python

Primary package path: calibrateddml

  • Main class: CalibratedDML
  • Main methods: fit, fit_from_nuisances, summary, confint
  • Adaptive layer: AdaptiveCalibratedDML
  • Adaptive Python API is intentionally narrower and experimental

R

Formula-free, data-first workflow

  • Main entry points: calibrated_dml() and calibrated_dml_from_nuisances()
  • Use summary() on fitted objects for printed results
  • Optional advanced backends through sl3 and SuperLearner
  • Adaptive R API is broader, but still binary-treatment only

Calibration

Calibration is part of the inferential pipeline, not just a prediction fix

In calibrated DML, nuisance functions are calibrated after fitting and before the debiasing step. The point is not to tell a ranking story; it is to improve the nuisance layer used by the doubly robust estimator so inference remains reliable when one nuisance is estimated much better than the other.

Think of calibration here as a post-hoc nuisance adjustment inside the causal estimator, not as a separate prediction product.

Conceptually

The package fits or accepts cross-fitted nuisance estimates, calibrates them, and then debiases using the calibrated nuisances. That ordering is the central design idea.

Practically

This is why the package is aimed at users who care about treatment-effect inference, overlap and propensity modeling, and defensible confidence intervals, not just prediction accuracy.
