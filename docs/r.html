R Package

The R interface is a first-class path for calibrated DML workflows.

The R package supports standard calibrated DML for categorical treatments, direct nuisance-matrix workflows, and binary-treatment adaptive estimators. It is especially well suited for users who want to plug into sl3, SuperLearner, or custom nuisance backends while keeping the inferential layer in a single package.

Install Main Entry Points

R Quick Summary

Standard estimator calibrated_dml() handles categorical treatment.
Direct nuisance path calibrated_dml_from_nuisances() is built in.
Adaptive scope adaptive_calibrated_dml() is binary-treatment only.

Compact R Example

fit <- calibrated_dml(
  data = df,
  outcome = "Y",
  treatment = "A",
  covariates = c("W1", "W2", "W3"),
  control_level = 0,
  outcome_model = "lasso",
  treatment_model = "lasso",
  calibration_method = "auto",
  inference = "wald"
)

summary(fit)

Entry Points

Main R entry points

The R API is organized around whether nuisances are fit inside the package or supplied directly, plus a separate adaptive path for binary treatment.

Start with the standard estimator unless you have a specific adaptive or external-nuisance need.

Standard

calibrated_dml()

  • Categorical treatment support in the standard estimator
  • Fits nuisances internally when mu_mat and pi_mat are omitted
  • Returns fitted objects with printed summaries
  • Supports wald, bootstrap, and jackknife

Direct Nuisance Path

calibrated_dml_from_nuisances()

  • Supply cross-fitted mu_mat and pi_mat directly
  • Useful for custom nuisance pipelines and reproducibility checks
  • Still runs the calibration, debiasing, and inference layers
  • Works with explicit treatment-level alignment

Backends

Built-in and advanced nuisance backends

The standard R estimator supports built-in model names and also leaves room for richer nuisance-learning stacks when you want to bring in external learners.

This is where the R package is broader than the lean Python package interface.

Built-in choices

Standard built-in model names include options such as "mean", "lm", "lasso", "gam", "random_forest", "boosted_trees", and "auto".

sl3 integration

Advanced users can fit nuisances through the tlverse ecosystem when they want learner stacks or richer cross-validated pipelines.

SuperLearner integration

The package also leaves room for SuperLearner libraries when that is the preferred nuisance-estimation path.

Estimator Families

Standard versus adaptive estimators

The R package exposes both the standard calibrated DML estimator family and a broader adaptive binary-treatment layer.

Adaptive methods are available, but they are still not the default recommendation for routine work.

Routine Use

Standard calibrated DML

Use the standard estimator for most empirical work. It handles categorical treatment directly and keeps the inferential target clear: arm means and treatment-vs-control contrasts.

Advanced

adaptive_calibrated_dml()

The adaptive R API is binary-treatment only and intended for users who explicitly want plugin or calibrated R-learner style adaptive methods.

  • Binary-treatment only
  • Supports broader adaptive modes than Python
  • Inference can be less stable than standard calibrated DML

Defaults

Practical defaults and inference choices

For most users, the goal is to keep the nuisance-learning side flexible while keeping the inferential choices explicit and boring.

Good defaults lower friction, but the user should still know which inference mode they are asking for.

Default recommendation

Start with the standard estimator, use the package-managed nuisance path unless you already have cross-fitted nuisances, and treat adaptive methods as deliberate advanced choices.

Inference modes

The standard R interface supports "wald", "bootstrap", and "jackknife". Choose the uncertainty layer explicitly rather than inheriting it by accident.
